1. FIRST: FINISH THE LIVE CUSTOMER LOGIN CHECK
====================================================================

Open in a browser (same host for all steps):

  https://bena-origins.onrender.com/api/v1/auth/login?returnTo=/

Sign in with a real customer account.

Then open:

  https://bena-origins.onrender.com/api/v1/auth/session

Expected:
  { "enabled": true, "authenticated": true, "customer": {...}, "csrfToken": "..." }

Then:

  https://bena-origins.onrender.com/api/v1/account/me
  https://bena-origins.onrender.com/api/v1/account/orders
  https://bena-origins.onrender.com/api/v1/account/addresses

If account/orders fails with an access error:
  Shopify Admin -> Headless -> Be Na Store Headless -> Customer Account API
  -> Permissions: enable customer_read_customers + customer_read_orders
  -> Submit/Save.

If login fails:
  invalid_client  -> Render Client ID/secret does not match the current Shopify client.
  invalid_token   -> JS-origin mismatch (should not apply to Confidential; report it).
  redirect_uri    -> callback in Shopify must be exactly:
                     https://bena-origins.onrender.com/api/v1/auth/callback
  state cookie    -> must open callback on the Render host over HTTPS.

After a successful login, delete the OLD Customer Account API credentials in
Shopify (keep the new ones).

Record result:
  [ ] /auth/session authenticated
  [ ] /account/me works
  [ ] /account/orders works
  [ ] /account/addresses works

5. FRONTEND KICKOFF — DECISIONS
====================================================================

Recommended: separate frontend repo, e.g. `BeNa-Storefront`, deployed on
Vercel/Netlify/Cloudflare Pages. Alternative: `frontend/` inside the backend
repo (Render ignores it). Decide before scaffolding.

Stack:
  React + TypeScript + Vite + Tailwind CSS + React Router + Socket.IO client
  TanStack Query (server state) and a small cart/auth context
  Vitest + React Testing Library; Playwright later for e2e

API base:
  VITE_API_BASE_URL=https://bena-origins.onrender.com/api/v1
  VITE_SOCKET_URL=https://bena-origins.onrender.com
  VITE_SITE_URL=https://benaorigins.de

No Shopify secrets in VITE_*.

IMPORTANT — cookies and cross-site:
  Render (`onrender.com`) and the storefront (`benaorigins.de`) are different
  sites. The session cookie is HttpOnly, Secure, SameSite=Lax and will NOT be
  sent by a browser from benaorigins.de to onrender.com on XHR/fetch.
  Options:
    A. Add a Render custom domain `api.benaorigins.de` (DNS change — approval).
    B. Proxy `/api` and `/socket.io` through the storefront dev/prod host.
  For local dev, add a Vite proxy `/api` -> Render so the browser sees
  same-origin requests and cookies work. Do not test auth from localhost
  directly against the Render host and expect the cookie to be sent.

CORS:
  Backend currently allows:
    https://benaorigins.de
    https://www.benaorigins.de
    https://bena-origins.onrender.com
  Add the exact frontend dev/preview origin if calling the API directly.

  npm create vite@latest bena-storefront -- --template react-ts
  cd bena-storefront
  npm install
  npm install react-router-dom @tanstack/react-query socket.io-client
  npm install -D tailwindcss @tailwindcss/vite vitest @testing-library/react \
    @testing-library/jest-dom jsdom @types/node

Add Tailwind per current Tailwind docs (v4 uses @tailwindcss/vite).
Add `.env.local`:

  VITE_API_BASE_URL=https://bena-origins.onrender.com/api/v1
  VITE_SOCKET_URL=https://bena-origins.onrender.com
  VITE_SITE_URL=https://benaorigins.de

For local dev proxy (recommended), Vite config:

  server: {
    proxy: {
      '/api': { target: 'https://bena-origins.onrender.com', changeOrigin: true, secure: true },
      '/socket.io': { target: 'https://bena-origins.onrender.com', ws: true, changeOrigin: true }
    }
  }

Then use same-origin `/api/v1` during development. In production either use the
proxy on the storefront host or the custom `api.benaorigins.de` domain.

7. FRONTEND FOLDER TARGET
====================================================================

  src/
    app/            providers, router, layouts
    api/            fetch wrapper, endpoints, query keys
    types/          copy from backend src/types (api/domain/audit/auth) or generate from OpenAPI
    features/
      catalog/      products, collections, search
      product/      detail, variants, images, metafields
      cart/         cart drawer, lines, buyer identity, discount codes
      account/      login state, profile, orders, addresses
      policies/     shipping/refund/privacy/terms/legal
      seo/          metadata + JSON-LD consumers
    components/     Button, Price, Quantity, Skeleton, ErrorState
    hooks/          useSession, useCart, useProducts
    lib/            money, units, formatting
    styles/         Tailwind tokens/theme
    routes/         Home, Products, Product, Collection, Search, Cart, Policies,
                    Account, Orders, Addresses, 404

Frontend rules:
  - One fetch wrapper for { success, data, meta, error }.
  - Always read meta.warnings in development (fixture/live status).
  - Use cursor pagination: meta.pagination.endCursor -> ?after=
  - URL-encode cartId (it may contain ?key=).
  - Never build checkout URLs manually; redirect to data.checkoutUrl.
  - Never call Shopify directly; use the backend only.
  - Do not store Shopify tokens; store only cart id and session status.
  - On cart 404: discard stored cart id and create a new cart.
  - Checkout redirect leaves the app (Shopify-hosted).
